# Criterios para Documentar: Cuándo, Qué y Cómo Priorizar

Basado en la metodología MIMT M2, Ventajas Competitivas, y el ciclo grabar-documentar-optimizar.

---

## ¿Vale la pena documentar este proceso?

No todo merece un SOP. Antes de arrancar, evaluá estos criterios:

### Criterios de priorización (MIMT M2)

Los 3 más importantes para Muta:

1. **Conexión con objetivos personales de las socias**: ¿documentar esto libera tiempo o mejora
   algo que las socias quieren lograr este año? Si sí, tiene prioridad alta.

2. **Prioridades estratégicas del trimestre**: ¿está vinculado a un proyecto activo en Asana?
   ¿Aparece como rojo o amarillo en el semáforo de sistemas críticos? Si sí, documentar ahora.

3. **Restricciones actuales**: ¿este proceso es un cuello de botella? Evaluá:
   - ¿Está por debajo de estándares mínimos?
   - ¿Consume mucho tiempo de las socias?
   - ¿Su falta de documentación frena la productividad de otros procesos?

### Señales de que NO vale la pena documentar ahora

- Se hace menos de 1 vez por trimestre y no es crítico.
- Cambiaría si el negocio crece (documentarlo hoy sería trabajo tirado).
- Está dentro de un proceso más grande que todavía no se documentó: primero el macro.

## El ciclo grabar-documentar-optimizar (MIMT M2)

Este es el flujo correcto para documentar cualquier proceso en Muta:

### Paso 1: Grabar
Antes de escribir nada: grabate (o grabá al equipo) haciendo el proceso real.
Sin editar, sin prepararse. Así como se hace hoy.

**Por qué:** Lo que se documenta desde la memoria siempre omite pasos.
La grabación captura lo que realmente sucede.

### Paso 2: Documentar
Con la grabación (o transcripción) como base, armar el documento paso a paso.

**Tips clave:**
- Si el proceso grabado dura más de 20 minutos, probablemente son **varios procesos**.
  Separarlos en documentos distintos antes de escribir, no un "choclo" de 300 pasos.
- Si durante la documentación detectás una optimización obvia (sin necesidad de investigar),
  incorporala directamente. Si requiere investigar, anotala aparte y seguí.
- Puede escribirlo quien lo hizo u otra persona. Si es otra, quien ejecuta el proceso
  debe validar que el documento refleja la realidad.

### Paso 3: Optimizar
Con el proceso ya documentado, buscá mejoras de **triple impacto**:
procesos que simultáneamente → ahorran tiempo + mejoran resultado para el cliente + aumentan ingresos.

**Preguntas para detectar desperdicios:**
- ¿Hay pasos que se repiten innecesariamente?
- ¿Hay algo que solo puede hacerlo una persona específica? (cuello de botella)
- ¿Hay pasos manuales que podrían automatizarse?
- ¿Algún paso consume mucho tiempo con poco impacto en el resultado final?

**Objetivo mínimo:** recuperar al menos 20% del tiempo que toma el proceso
manteniendo o mejorando los resultados. (Promedio MIMT 2022: 30% de recupero.)

Si no llegás a ese 20% con las mejoras identificadas → no pasés al siguiente proceso.
Pausá, revisá, ajustá.

---

## Cuántos procesos documentar

- **Mínimo por mes:** 2 procesos completos (grabar + documentar + optimizar).
- **No hay límite máximo:** en el bootcamp hubo quienes llegaron a 6-7 en un mes.
- **Orden recomendado:** empezá por el proceso que tenga el semáforo más rojo
  y que más dependa de las socias para ejecutarse.

---

## Cuándo un proceso está "vivo" (y no solo escrito)

Un SOP vivo cumple estas condiciones (MIMT M4):
- Tiene un **disparador claro**: algo que le recuerda al equipo cuándo usarlo.
- Se usa con el documento a mano, no de memoria.
- Tiene una **fecha de revisión** programada (el controlador de procesos de Asana).
- Genera una **recompensa** cuando se cumple: el hábito se sostiene con el ciclo
  disparador → conducta → recompensa.

Si el SOP existe pero nadie lo usa → no es un proceso vivo, es un archivo.
